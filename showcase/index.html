01 / THE IDEA

Information doesn't
arrive ready to query.

A web page can contain navigation, repeated interface elements, multiple topics and unstable links. Ingestion turns that raw material into structured, traceable content. Retrieval then uses an index to find relevant passages.

01↗

Find the right sources

Discover candidate pages, or select repository files from a pinned Git commit. A site is a collection of documents, not a single blob.

02≡

Preserve what matters

Extract useful content, normalize to Markdown and retain document titles, URLs, headings and source identity.

03◈

Index with boundaries

Chunk content, apply embeddings via the configured provider, and synchronize records without deleting unseen pages from partial crawls.

04⌕

Retrieve with provenance

Search for relevant passages and keep enough metadata to trace each result to its original document.

03 / REAL ARCHITECTURE

One ingestion model.
Different downstream paths.

The repository deliberately separates acquisition, normalized Markdown, vector records, and storage provider implementations. These choices affect operations, credentials and what can be safely reused.

01HOST-PROVIDED EMBEDDINGS

Vector indexing

RemoteSourceIngestion accepts an EmbeddingProvider plus a VectorStore. The host produces vectors; Qdrant and Weaviate implementations persist the resulting records.

Markdown → chunks → embeddingProvider → VectorStore
Incremental reconciliation uses content fingerprints, pipeline revision and snapshot completeness.
02FILE-BASED KNOWLEDGE STORE

Knowledge-base adapters

KnowledgeBaseVectorStoreAdapter receives files and metadata. Weaviate/Qdrant adapters can split and use provider-native vectorization; Qdrant can also accept host embeddings.

Markdown files → adapter → provider-specific indexing
File ingestion and precomputed-vector synchronization are different contracts; they must not be conflated.
⊘

Private-network protection

DNS resolution and redirects must honor URL safety rules. An interface sample does not establish that a remote URL was fetched.

⧖

Execution budgets

Bound page count, bytes, elapsed time, chunk count and embedding inputs. Limits can produce partial results.

◎

Reconciliation safety

An incomplete crawl cannot prove that missing documents were deleted from the source. Prevent destructive sync decisions.

◇

Traceable results

Preserve canonical URLs, headings, namespace and run correlation so retrieved snippets remain auditable.

04 / BUILD WITH THE LIBRARY

From the model
to real code.

This repository is a Node.js/TypeScript library, not a publicly published npm package. Install from source and inject your provider implementations; importing the entry point does not start a crawl.

example.ts · INTERFACE SKETCH
import { RemoteSourceIngestion } from "remote-ingestion-retrieval";

// Supply implementations from your host application.
const ingestion = new RemoteSourceIngestion({
  pipelineRevision: "docs-v1:embedding-v1",
  embeddingProvider,
  vectorStore
});

const now = new Date();
try {
  const outcome = await ingestion.runSourceInsertion({
    source: {
      id: "product-docs",
      type: "website",
      url: "https://docs.example.com/",
      createdAt: now,
      updatedAt: now
    },
    namespace: "product_docs"
  });
  console.log(outcome.status);
} finally {
  await ingestion.close();
}

The embedding provider and vector store are intentionally undefined placeholders. This example is not executable without host configuration.
